---
name: Clan held-blook effects
description: Registry rules for clan-held blook powers, auto-collected token mine semantics, and frontend image URL resolution.
---

- **Effect registry is the single honest source.** Every ability string shown in the UI must map to a real server-enforced consumption hook (pack luck, pack price, bonus copy, sell price, daily claim, Base production). Never list an effect without wiring its consumption site.
  **Why:** Advertised-but-fake effects were explicitly rejected — players must get exactly what the ability text promises.
- **Every blook now has an effect** (`clanEffectForBlook` never returns null): Mysticals get registry auras, Uncommons get the shared-key charm aura (both `kind: "aura"`), everything else pays the token mine (`kind: "mine"`, its hook is the auto-settle ledger). Clan `activeEffects` chips list auras only; mine output is summarized by `heldProduction.payingCount` — never render one chip per rarity.
- **Held pay rates (Mystical mine 75/hr, Chroma 10/hr):** FIRST copy of each aura-registered Mystical (held-row id order) is aura-only 0/hr; duplicate copies pay the 75/hr mine; a Mystical with NO registry aura (e.g. Nitendo Switch) pays 75/hr on EVERY copy; Chromas 10/hr. **Why:** flat every-Mystical-pays was explicitly rejected — the mine rate belongs to duplicates/aura-less copies only. Classification is FUNCTIONAL and must stay identical between the clan detail route's duplicate map and the settle sweep (both id-ordered, both aura-registry-aware).
- **Clan-hold ban:** Miscellaneous-pack blooks (incl. the 1k gamble blook — its def.pack IS "Miscellaneous") can never be committed to a hold: `isClanHoldBanned(pack)` guards placement, /me/blooks returns clanEffect null for them, and the picker hides them. Verified zero banned rows held in dev AND prod before shipping, so no cleanup sweep was needed.
- **Settle before any held-set change (mandatory-abort):** withdraw, member leave, and disband call `settleClanMembersMines(clanId)` BEFORE deleting or reclassifying rows, and a settle failure ABORTS the mutation (errors propagate; no catch-and-continue — that would let the next sweep reprice the failed member's interval at the new rates). **Why:** the member clock prices the whole unsettled interval at CURRENT rates — removing the first copy of a duplicated Mystical flips the survivor's mine rate to 0/hr; leaving deletes the member row the clock lives on. Withdraw pre-checks row ownership/unlock (unlocked read) before settling so strangers can't hammer arbitrary clans into settle work. Accepted residual: clocks advance only on whole tokens, so the settle→delete gap reprices <1 token per member; no clan-wide lock/ledger is warranted for that.
- **Batch placement:** POST held-blooks takes `blookNames[]` (≤30, repeated names = multiple copies); per-entry outcomes `held|lost|unavailable` — a missing copy is skipped, never a whole-batch failure; one shared withdrawableAt; collector badge synced once at end. Client sends name×count map flattened; directory sort = my clan pinned, then level desc.
- **Aura stacking rules (user call, Aug 2026):** Mystical auras are non-stacking booleans resolved from a Set of held blook names; the Uncommon charm is the ONE stacking effect — count raw held rows (copies of the same blook count), never the deduped name Set. Banned clans and non-members get neutral multipliers.
- **Uncommon charm:** every held Uncommon adds a flat +0.001x pack luck per copy, additive onto the luck multiplier in the shared open path (Top gamble pack exempt). The charm is the Uncommon's WHOLE power: held Uncommons pay ZERO mine tokens. The registry emits one shared-key chip; the clan route rewrites its label with the stacked total (×N — +0.00Nx). This replaced the old Base Uncommon-miner luck — don't add either back.
- **Chip label format:** aura/chip labels are `Source — Perk` with an em dash; the client splits on the first em dash to render compact two-line chips (perk on top, source below). Keep that format for any new effect label.
- **Bonus-copy guard:** the double-pull effect must exclude the limited-supply Top pack, or its global 100-supply economy breaks.
- **Time-bounded multipliers:** any effect applied over lazily-accrued time must be weighted from when the effect became active — `max(member joinedAt, held blook placedAt)` — never retroactively over the whole interval. See base-progression.md for the settlement math.
- **Held token mine clock:** per-member column `clan_members.clan_tokens_last_at` (NOT NULL DEFAULT now(); prod receives it via the Publish schema diff). Held blooks accrue rarity-scaled tokens/hr (Common 1 → Chroma 10; Mystical mine copies 75 — see the rates bullet for first-copy/aura-less rules; Uncommon 0 — luck charm instead; other unknown rarities floor to 1 in the lib, but settle's `getBlookDef` fallback is 0). Each entry accrues from `max(lastCollectedAt, placedAt, now − 24h)`, summed then floored. Detail view shows payingCount + per-member rate only (no unclaimed figure) and must use the same rate helper the settle path uses.
- **Auto-collect, no endpoint:** mine pay is deposited by a server sweep (boot + every 5 min) that settles each eligible member (non-banned clan, ≥1 held blook via EXISTS) in their OWN transaction with try/catch isolation. The manual collect endpoint was fully removed (spec, server, client) — don't resurrect it; the 24h horizon stays as an accrual cap only.
- **Settle lock order:** player row → member row FOR UPDATE → held rows FOR UPDATE ordered by id. The held-row locks serialize settling against withdraw/disband (a row deleted mid-settle would otherwise still be paid through `now`); the id ordering keeps concurrent settles deadlock-free, and the player-row lock makes overlapping sweep ticks race-safe (no double-pay). Never advance the clock when payout is 0 — that silently destroys fractional accrual.
- **Frontend image rule:** prefix `/api/storage` only for `/objects/...` paths (object-storage uploads); paths already starting with `/api/` (built-in content) are used as-is. Wrongly prefixing built-in paths was the cause of broken held-blook and banner images.
